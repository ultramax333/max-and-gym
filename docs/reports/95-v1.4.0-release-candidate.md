# Max & Gym 1.4.0 release candidate

Date: 2026-08-13

Scope: the three committed modern-interface checkpoints plus release identity and documentation.

## Included checkpoints

- `41a1c72` — active workout modernization;
- `408dc92` — workout generator modernization;
- `200182a` — full application interface modernization.

## Release impact

- application version: `1.3.16` → `1.4.0`;
- database schema, export format, exercise seed, program seed, generator and cache identity: unchanged;
- Android application ID and signing contract: unchanged;
- runtime network origins and local-first data model: unchanged;
- no production dependency or external asset added.

## Candidate validation

The release candidate must pass `npm run quality`, the Android web sync/build smoke, Gradle debug unit tests and debug APK assembly. The pull-request workflows repeat the quality and Android gates. After acceptance and merge, the trusted `master` workflows create the signed, versioned APK, verify its signature, publish GitHub Release `v1.4.0`, include the installer in the Pages artifact and run the deployed release-identity smoke.

## Publication boundary

Repository policy forbids the release author from merging their own pull request. Publication therefore stops at a verified release PR. Production deployment and signed APK publication begin automatically from the accepted merge to `master`.

## Rollback and recovery

No database or backup migration is required. Before update testing, retain a current `.maxgym` backup outside app storage. After a signed release is published, corrections use a new semantic version and higher Android `versionCode`; the existing release asset is not replaced.
