# Max & Gym v1.7.0 release candidate

Date: 2026-08-16

## Requirements

- `V1.7-R1`: rotate generated exercises intelligently without random or forced changes.
- `V1.7-R2`: let the user defer an occupied-machine exercise without losing progress.
- `V1.7-R3`: allow a safe compatible replacement during a workout.
- `V1.7-R4`: improve pre-session visibility and post-session recap without automatic load progression.

## Current and target behavior

Previously, quick generation hard-blocked the latest generated exercises and remembered only two sessions; the active workout exposed generic exercise switching but no explicit occupied-machine flow; preview timing was summarized only as one total; and the summary did not provide an exercise-by-exercise recap.

The v1.7 target uses a deterministic recent-use penalty across four generations, exposes `Do later` and pre-set replacement controls, adds accessible preview reordering and a time breakdown, and records a clear exercise recap. Previous values remain local history and are not transformed into automatic progression.

## Architecture and data safety

- Rotation state remains in local `appMeta`; no account or network service is introduced.
- Exercise replacement is an idempotent critical operation committed with the session update.
- Replacement is rejected after any set value has been logged, preventing historical identity rewrites.
- Optional original-exercise snapshot fields require no IndexedDB index or schema migration.
- Existing v1.6 readers safely ignore the optional fields, providing a forward rollback path.

## Accessibility and privacy

- Reordering uses named up/down controls instead of drag-only interaction.
- Occupied-machine alternatives use a full-screen workout panel with named controls.
- No personal loads, repetitions or notes enter diagnostics.
- No new runtime network origin, telemetry, cloud store or donor code is introduced.

## Known limitation

An exercise can be replaced in place only before its first logged set. Afterward, `Do later` remains available; this deliberate boundary protects completed-set history.

## Rollback

Revert the v1.7 checkpoint commit. No database migration rollback is required; optional replacement snapshot fields and local rotation metadata can remain without affecting v1.6 behavior.
